## 1. โจทย์

ปัจจุบันแผนฝึกอบรมประจำปีเก็บอยู่ในไฟล์ Excel ไฟล์เดียว (`รวมแผนอบรม 2569.xlsx`)
ซึ่งใช้ได้ดีในฐานะ "แผน" แต่ใช้ติดตามผลไม่ได้ เพราะไม่มีใครรู้ว่าพนักงานคนไหน
เข้าอบรมหัวข้อไหนไปแล้วบ้าง จนกว่าฝ่ายบุคคลจะไล่ถามทีละคน

ระบบที่ต้องการมีสามส่วน

1. แจ้งเตือนล่วงหน้าก่อนถึงวันอบรม
2. แจ้งเตือนอีกครั้งเมื่อการอบรมจบลง พร้อมลิงก์
3. ลิงก์นั้นเปิดไปยังหัวข้ออบรมที่เกี่ยวข้อง และเมื่อพนักงานยืนยัน ระบบจะติ๊กถูก
   ช่อง "เข้าอบรมแล้ว" ให้อัตโนมัติ โดยฝ่ายบุคคลไม่ต้องกรอกเอง

## 2. สิ่งที่พบในไฟล์ Excel ปัจจุบัน

ไฟล์มี 10 ชีต แบ่งเป็นสองรูปแบบ

**ชีตแผนรวม** — `รวมแผนอบรม 2569`, `รวมแผนอบรม 2568 rev.01`, `rev.02`,
`ส่งเสริม`, `ควบคุมฯ`, `สำนักงาน` มี 14 คอลัมน์

ลำดับ, รายชื่อผู้เข้าอบรม, ตำแหน่งผู้เข้าร่วมอบรม, ความรู้แต่ละตำแหน่งที่ควรมี,
วันเดือนปีที่จะส่งพนักงานอบรม, จำนวนชั่วโมง, ค่าใช้จ่ายที่คาดว่าจะเกิดขึ้น,
ประเภทการอบรม (ภายใน/ภายนอก), เรื่อง/เนื้อหาของการอบรม, ประโยชน์และการนำไปใช้,
อนุมัติ, ไม่อนุมัติ, สาเหตุที่ไม่อนุมัติ, หมายเหตุ

**ชีตรายบุคคล** — `ทรรศน์กมล`, `นิตยา`, `พรทิพา`, `กานต์ธีรา`
เป็นบันทึกประวัติการอบรมจริงรายคน มีคอลัมน์ รายชื่อ, ตำแหน่ง, หัวข้อ,
บริษัท/สถาบันที่ฝึกอบรม, สถานที่จัดอบรม, ช่วงเวลาที่อบรม, รูปแบบ (Online/On-Site),
วันที่ฝึกอบรม, ผู้ฝึกอบรม

ชีตรายบุคคลสองชีตหลัง (`พรทิพา`, `กานต์ธีรา`) มีเพียง 6 คอลัมน์ ไม่มีสถานที่
ช่วงเวลา และรูปแบบ โครงสร้างจึงยังไม่ตรงกันระหว่างชีต

## 3. อุปสรรคที่ต้องแก้ก่อนสร้างระบบ

ข้อเหล่านี้ไม่ใช่เรื่องความสวยงามของไฟล์ แต่เป็นเงื่อนไขที่ทำให้ระบบอัตโนมัติ
ทำงานไม่ได้เลยถ้าไม่แก้

**3.1 วันที่เป็นข้อความอิสระ และเป็น พ.ศ.**

ค่าที่พบจริงในไฟล์ ได้แก่ `08-09/08/2569`, `09/08/2569 , 11/08/2569`,
`27/08/2569`, `ส.ค`, `ส.ค - ก.ย.`, `28-31 ต.ค. 68`, `เดือนกรกฎาคม 2568`

การแจ้งเตือนล่วงหน้า 7 วันต้องคำนวณจากวันที่ที่เป็นชนิดวันที่จริง ไม่ใช่ข้อความ
และต้องเป็น ค.ศ. เพราะเครื่องมือทุกตัวคำนวณบนปฏิทินสากล แผนบางรายการระบุเพียง
ชื่อเดือน ซึ่งยังแจ้งเตือนไม่ได้จนกว่าจะกำหนดวันจริง

**3.2 ผู้เข้าอบรมหลายคนอยู่ในเซลล์เดียว**

เช่น `1.นางสาวพริศรา ยี่รัญศิริ\n2.นางสาวทรรศน์กมล ศรีคำภา\n3....`

เมื่อพนักงานสามคนอยู่ในแถวเดียว จะติ๊กถูกแยกรายคนไม่ได้ ระบบต้องแยกเป็น
หนึ่งแถวต่อหนึ่งคนต่อหนึ่งหลักสูตร

**3.3 ช่องติ๊กเป็น ActiveX control**

ช่อง "อนุมัติ" และ "ไม่อนุมัติ" ในไฟล์ปัจจุบันคือ ActiveX checkbox จำนวน 66 ตัว
ที่ลอยอยู่เหนือเซลล์ ไม่ได้เก็บค่าไว้ในเซลล์ ทำให้ระบบภายนอกอ่านหรือเขียนค่าไม่ได้
และยังเปิดใช้ได้เฉพาะ Excel บน Windows เท่านั้น เปิดบน Excel Online หรือ Mac
จะไม่ทำงาน

ต้องเปลี่ยนเป็นค่าในเซลล์ตรง ๆ คือ `ใช่` หรือ `ไม่ใช่`
แล้วใช้ Conditional Formatting แสดงเครื่องหมายถูกแทน หน้าตาเหมือนเดิม
แต่อ่านและเขียนด้วยระบบได้

**3.4 ไม่มีช่องทางติดต่อพนักงานในไฟล์**

ไฟล์มีแต่ชื่อกับตำแหน่ง ไม่มีอีเมลบริษัท ต้องเพิ่มตารางพนักงานพร้อมอีเมล
ซึ่งเป็นอีเมล M365 เดียวกับที่ใช้เข้า Teams

**3.5 "อนุมัติ" กับ "เข้าอบรมแล้ว" เป็นคนละเรื่อง**

ช่องติ๊กที่มีอยู่ตอนนี้คือการอนุมัติแผนโดยผู้บริหาร ไม่ใช่การยืนยันว่าเข้าอบรมจริง
ระบบใหม่ต้องมีสองสถานะแยกกัน มิฉะนั้นการติ๊กอัตโนมัติจะไปทับผลการอนุมัติ

## 4. สถาปัตยกรรม

ใช้เฉพาะสิ่งที่มีในสิทธิ์การใช้งาน Microsoft 365 ที่บริษัทมีอยู่แล้ว
ไม่มีค่าใช้จ่ายเพิ่ม ไม่ต้องเช่าเซิร์ฟเวอร์ ไม่ต้องติดตั้งอะไรบนเครื่องพนักงาน

```
ไฟล์ Excel บน SharePoint / OneDrive for Business
  │  (จัดเป็น Excel Table สามตาราง)
  │
  ├─ Power Automate: Flow A — แจ้งเตือนล่วงหน้า
  │     ทำงานทุกวัน 08:00 อ่านตาราง หาแถวที่ครบเงื่อนไข
  │     ส่ง Teams / อีเมล ก่อนอบรม 7 วัน และ 1 วัน
  │
  ├─ Power Automate: Flow B — แจ้งเตือนหลังอบรมจบ
  │     ทำงานทุกวัน 08:00 หาแถวที่อบรมจบเมื่อวาน
  │     ส่งการ์ดพร้อมปุ่มยืนยันเข้า Teams และอีเมลสำรอง
  │
  ├─ Power Automate: Flow C — รับคำยืนยัน
  │     รับผลจากปุ่ม เขียนกลับเข้าตาราง Enrollments
  │     ตั้ง เข้าอบรมแล้ว = ใช่ บันทึกวันเวลาและผู้ยืนยัน
  │
  └─ Power Automate: Flow D — สรุปให้ฝ่ายบุคคล
        ทุกวันจันทร์ 09:00 ส่งรายการที่ยังไม่ยืนยันให้ HR
```

ฝ่ายบุคคลยังทำงานบนไฟล์ Excel เหมือนเดิมทุกประการ เพียงแต่ช่องที่เคยต้องกรอกเอง
จะถูกเติมให้อัตโนมัติ

Power Automate Premium

### ทางเลือก ข — อีเมลพร้อมปุ่มตอบกลับ

เหมาะกับพนักงานที่ไม่ได้ใช้ Teams เป็นประจำ ออกแบบให้ใช้คู่กับทางเลือก ก ได้
โดยส่ง Teams ก่อน ถ้าไม่ตอบใน 3 วันจึงส่งอีเมล

### ทางเลือก ค — ลิงก์ไปยัง Microsoft Forms

ถ้าต้องการ "ลิงก์" จริง ๆ ตามที่โจทย์บอก ใช้ Microsoft Forms หนึ่งฟอร์ม
แล้วส่งลิงก์ที่เติมคำตอบล่วงหน้าไว้แล้ว (prefilled link) โดยฝัง `รหัสการลงทะเบียน`
ลงไปในลิงก์

```
https://forms.office.com/r/XXXXXXXX?ENR=ENR-2569-0071
```

พนักงานเปิดลิงก์ เห็นชื่อหัวข้ออบรมที่ถูกเติมมาแล้ว กดยืนยัน ระบบติ๊กถูกให้

ข้อควรระวังด้านความปลอดภัย ตั้งค่าฟอร์มเป็น "เฉพาะบุคคลในองค์กรตอบได้"
เพื่อให้ Forms บันทึกอีเมลผู้ตอบจาก SSO แล้วให้ Flow ตรวจว่าอีเมลผู้ตอบตรงกับ
เจ้าของ `รหัสการลงทะเบียน` นั้นจริง ถ้าไม่ตรงให้ปฏิเสธ มิฉะนั้นใครก็ตามที่ได้ลิงก์ไป
จะยืนยันแทนคนอื่นได้ และห้ามใช้เลขรันนิ่งเรียงกันเป็น `รหัสการลงทะเบียน`
ในลิงก์สาธารณะ เพราะเดาต่อไปทีละเลขได้

ข้อเสียของทางเลือกนี้คือต้องกดเปิดเบราว์เซอร์ ขั้นตอนมากกว่าสองทางเลือกแรก
อัตราการตอบกลับจะต่ำกว่า

### สิ่งที่เกิดขึ้นหลังพนักงานยืนยัน

1. Flow C รับผลการกดปุ่ม
2. ค้นแถวในตาราง Enrollments ด้วย `รหัสการลงทะเบียน`
3. ตรวจว่าผู้ตอบคือเจ้าของแถวนั้นจริง

6. ส่งข้อความสั้นกลับไปยืนยันให้พนักงานเห็นว่าบันทึกแล้ว

## 8. ข้อจำกัดที่ต้องรับทราบก่อนตัดสินใจ

**8.1 Excel ไม่ได้ออกแบบมาให้หลายคนเขียนพร้อมกัน**

ถ้าฝ่ายบุคคลเปิดไฟล์ค้างไว้ใน Excel บนเครื่อง (ไม่ใช่ Excel Online) ไฟล์จะถูกล็อก
และ Flow จะเขียนไม่ได้ การยืนยันของพนักงานจะหายไปเงียบ ๆ

ทางแก้ กำหนดให้เปิดไฟล์นี้ผ่าน Excel Online เท่านั้น หรือย้ายไปใช้ SharePoint List
ซึ่งรองรับการเขียนพร้อมกันโดยธรรมชาติ และยังเปิดดูในรูปแบบตารางแบบ Excel ได้
ข้อนี้เป็นความเสี่ยงที่ใหญ่ที่สุดของแนวทางที่ใช้ Excel เป็นฐานข้อมูล

**8.2 ขนาดข้อมูล**

Excel connector ของ Power Automate ดึงข้อมูลได้ครั้งละจำกัด และช้าลงมากเมื่อ
ตารางโตขึ้น ที่ปริมาณของบริษัท (พนักงานหลักสิบ หลักสูตรปีละไม่กี่สิบรายการ
Enrollments ปีละไม่กี่ร้อยแถว) ยังไม่เป็นปัญหา แต่ถ้าสะสมหลายปีในไฟล์เดียว
ควรแยกไฟล์ตามปี

**8.3 วันที่จาก Excel connector**

Excel เก็บวันที่เป็นตัวเลขอนุกรม (serial number) Power Automate จะได้ค่าเป็น
ตัวเลขเช่น `46262` ไม่ใช่ `2026-08-28` ต้องแปลงใน Flow ทุกครั้ง เป็นจุดที่
ผิดพลาดบ่อยที่สุดตอนพัฒนา ต้องทดสอบให้ครบ

**8.4 ไม่มีการล็อกอิน แต่ต้องพิสูจน์ตัวตน**

ระบบนี้ไม่มีหน้าล็อกอินของตัวเอง ทุกทางเลือกในข้อ 7 พึ่งพาการยืนยันตัวตนของ
Microsoft 365 ที่พนักงานล็อกอินอยู่แล้ว ซึ่งปลอดภัยกว่าการสร้างรหัสผ่านชุดใหม่
แต่แปลว่าพนักงานทุกคนที่ต้องยืนยันต้องมีบัญชี M365 ของบริษัท

**8.5 เรื่องที่ระบบนี้ยังไม่ทำ**

- ไม่ออกใบประกาศนียบัตร
- ไม่เก็บไฟล์แนบ เช่น ใบเซอร์หรือรูปถ่ายวันอบรม (เพิ่มภายหลังได้ด้วย SharePoint)
- ไม่คำนวณชั่วโมงอบรมสะสมรายบุคคลเทียบกับเกณฑ์ที่กฎหมายกำหนด
- ไม่ทำงานแทนขั้นตอนอนุมัติแผน ซึ่งยังเป็นงานของผู้บริหารตามเดิม

### 10.1 เรื่องสิทธิ์ Power Automate ไม่ต้องไล่ตรวจทุกคน

Flow ทำงานภายใต้บัญชีของเจ้าของ Flow เพียงบัญชีเดียว พนักงานที่เหลือเป็นเพียง
ผู้รับข้อความ ไม่ต้องมีสิทธิ์ Power Automate ใด ๆ ทั้งสิ้น

จึงตรวจเพียงบัญชีเดียว และควรเป็นบัญชีกลางของฝ่ายบุคคล ไม่ใช่บัญชีส่วนตัวของใคร
เพราะถ้าเจ้าของบัญชีลาออก Flow ทุกตัวจะหยุดทำงานพร้อมกัน

ระบบนี้ออกแบบให้ใช้เฉพาะตัวเชื่อมต่อมาตรฐาน คือ Excel Online (Business),
Microsoft Teams, Office 365 Outlook และทริกเกอร์ตามกำหนดการ ทั้งหมดรวมอยู่ใน
สิทธิ์ Microsoft 365 ที่บริษัทมีอยู่แล้ว ไม่แตะตัวเชื่อมต่อระดับ Premium เลย
จึงไม่มีค่าใช้จ่ายเพิ่ม

วิธีตรวจใช้เวลาสองนาที อยู่ในหัวข้อ 0 ของ `docs/flow-build-guide.md`

### 10.2 การรับมือหลักสูตรที่ยังไม่มีวันที่

เมื่อวิทยากรเป็นผู้เลือกวัน แผนจึงมีช่วงที่ยังไม่มีวันแน่นอนอยู่เสมอ
ระบบจัดการเรื่องนี้ด้วยสามกลไก

1. หลักสูตรที่ `วันเริ่ม` ว่าง จะถูกข้ามโดยไม่เกิดข้อผิดพลาด ไม่ใช่ทำให้ Flow ล้ม
2. คอลัมน์ `ข้อความวันที่เดิม` เก็บข้อความอย่าง `ส.ค - ก.ย.` ไว้ให้ฝ่ายบุคคลเห็น
   ว่าเดิมวางแผนไว้ช่วงใด จะได้ตามวิทยากรได้ถูกช่วง
3. รายงานประจำสัปดาห์ (Flow D) จะเตือนว่ามีกี่หลักสูตรที่ยังไม่กำหนดวัน
   ทำให้ช่องว่างนี้ไม่หายไปเงียบ ๆ

เมื่อฝ่ายบุคคลกรอกวันลงไปเมื่อใด การแจ้งเตือนจะเริ่มทำงานกับหลักสูตรนั้นทันที
โดยไม่ต้องแก้ Flow

ตัวสีเทา เพราะเป็นประวัติที่ผ่านไปแล้ว ระบบจะไม่แจ้งเตือน และฝ่ายบุคคลไม่ต้อง
เสียเวลาย้อนไปกรอกวันที่ให้ครบ

สิ่งที่สคริปต์แก้ให้ระหว่างย้าย

- แยกรายชื่อที่เคยรวมอยู่ในเซลล์เดียว ออกเป็นหนึ่งแถวต่อหนึ่งคน
- รวมชื่อที่สะกดต่างกันแต่เป็นคนเดียวกัน เช่น `นางกานต์ธีรา ปัดวิชัย` กับ
  `นางสาวกานต์ธีรา ปัดวิชัย` และ `พลอยณภัช` กับ `พลอยนภัส`
- แปลงวันที่ที่ระบุชัดเจนเป็นคอลัมน์วันที่แบบ ค.ศ. เช่น `08-09/08/2569`
  และ `28-31 ต.ค. 68`
- ตัดรายการที่ไม่ใช่พนักงานออกจากทะเบียน เช่น `เกษตรกรเขตมุกดาหาร`
- แก้แผนกของทีมส่งเสริมการผลิต ซึ่งไฟล์เดิมสะกดว่า `ส่งสริมการผลิต` ตกตัว เ
- ยุบหลักสูตรซ้ำ เช่น `อบรมและซ้อมอพยบหนีไฟ` ในแผน กับ `อพยพหนีไฟ`
  ในชีตรายบุคคล ซึ่งเป็นรายการเดียวกัน

สิ่งที่สคริปต์จงใจไม่ตัดสินใจเอง ถูกรวบไว้ในชีต **สิ่งที่ต้องตรวจ** 41 รายการ
ฝ่ายบุคคลต้องเคลียร์ชีตนี้ให้หมดก่อนเปิดใช้ระบบ แบ่งเป็น

| ความสำคัญ | เรื่อง | จำนวน |
|---|---|---|
| สูง | อีเมล Microsoft 365 ยังว่าง | 29 |
| สูง | หลักสูตรปี 2569 ที่ยังไม่มีวันอบรม | 3 |
| สูง | ชื่อที่นามสกุลเดียวกัน ต้องยืนยันว่าคนเดียวกันหรือไม่ | 1 |
| สูง | หลักสูตรที่ถูกยุบรวม ต้องยืนยันว่าถูกต้อง | 1 |
| กลาง | พนักงานที่ไฟล์เดิมไม่ได้ระบุตำแหน่งจริง | 5 |
| ต่ำ | หลักสูตรที่ยังไม่ทราบสถาบันผู้จัด | 2 |

รายการ "ชื่อที่นามสกุลเดียวกัน" คือ `นางเบญจ์ ภูมิบุญ` กับ `นางเพลิน ภูมิบุญ`
สคริปต์ไม่รวมให้ เพราะชื่อต้นต่างกันมากพอที่จะเป็นคนละคนจริง ๆ ต้องให้ฝ่ายบุคคล
ตัดสิน การรวมผิดจะทำให้พนักงานคนหนึ่งหายไปจากระบบทั้งคน

## 13. การจองวันกับผู้จัด เพิ่มในเวอร์ชัน 0.3

**ยกเลิกแล้ว 23 กันยายน 2569** บริษัทตัดสินใจให้ผู้ดูแลระบบ 8 คนตกลงวันกับผู้จัดเองนอกระบบ
แล้วกรอก `วันเริ่ม` `วันจบ` ในชีต หลักสูตร เอง ไม่มีการ์ดขอจองวัน ไม่ต้องสร้าง Flow E
หลักสูตรที่ใกล้ช่วงวางแผนแต่ยังไม่มีวัน ไปขึ้นในอีเมลสรุปของ Flow D แทน

คอลัมน์ ผู้ประสานงาน อีเมลผู้ประสานงาน ส่งคำขอจองวันแล้ว วันที่ส่งคำขอล่าสุด ไม่มีใครใช้แล้ว ลบออกจากไฟล์จริงได้

### 13.1 ปัญหา

แผนอบรมส่วนใหญ่ระบุได้แค่ช่วงเดือน เช่น `ส.ค` หรือ `ส.ค - ก.ย.` เพราะวันจริง
ขึ้นอยู่กับความสะดวกของผู้จัดหรือวิทยากร ไม่ใช่ของบริษัท

การแจ้งเตือนล่วงหน้าต้องมีวันที่แน่นอน หลักสูตรที่ไม่มีวันจึงเป็นทางตัน
ในเวอร์ชันก่อน ระบบเพียงข้ามหลักสูตรเหล่านั้นไป แล้วรายงานให้ผู้ดูแลตามเอง
ซึ่งย้ายภาระกลับไปหาคน ไม่ได้แก้ปัญหา

### 13.2 วิธีแก้

แยกสถานะของวันอบรมออกจากสถานะการอนุมัติแผน เป็นคอลัมน์ `สถานะวันที่`
ที่มีสามค่า

| ค่า | ความหมาย | ระบบทำอะไร |
|---|---|---|
| `ยืนยันแล้ว` | รู้วันแน่นอน | แจ้งเตือนล่วงหน้าตามปกติ |
| `รอผู้จัดเลือกวัน` | รู้แค่ช่วงเดือน | ส่งการ์ดให้ผู้จัดเลือกวันเอง |
| `ยังไม่ระบุช่วง` | ไม่รู้แม้แต่เดือน | ไม่ทำอะไร รอผู้ดูแลกรอก |

พร้อมคอลัมน์ประกอบอีกห้าช่อง คือ `ช่วงวางแผนเริ่ม`, `ช่วงวางแผนจบ`,
`ผู้ประสานงาน`, `อีเมลผู้ประสานงาน`, `ส่งคำขอจองวันแล้ว` และ
`วันที่ส่งคำขอล่าสุด`

Flow E ทำงานทุกวันจันทร์ ส่งการ์ดที่มีปฏิทินให้ผู้จัด โดยปฏิทินเลือกได้
เฉพาะวันที่อยู่ในช่วงที่ผู้บริหารอนุมัติไว้ เมื่อผู้จัดกดยืนยัน ระบบเขียน
วันลงแผน เปลี่ยนสถานะเป็น `ยืนยันแล้ว` แล้ว Flow A เห็นหลักสูตรนั้นในรอบถัดไป
ทันที โดยไม่ต้องมีใครสั่งและไม่ต้องแก้ Flow

### 13.3 รายละเอียดที่ตัดสินใจไว้แล้ว

- **ถามสัปดาห์ละครั้ง ไม่ใช่ทุกวัน** การเลือกวันไม่ใช่เรื่องเร่งด่วนรายวัน
  และการถามทุกวันจะทำให้ผู้จัดเลิกตอบ
- **ปฏิทินไม่เสนอวันในอดีต** ช่วงที่วางแผนไว้อาจผ่านไปแล้วตอนที่ระบบเริ่มทำงาน
  ขอบล่างจึงเป็นค่าที่มากกว่าระหว่าง ช่วงวางแผนเริ่ม กับ พรุ่งนี้
  ถ้าช่วงหมดอายุทั้งช่วง ระบบเปิดกว้างให้ 120 วันแทนการปิดตาย
- **ปุ่ม ยังกำหนดวันไม่ได้** ผู้จัดตอบว่ายังไม่ได้ ก็ยังถือเป็นการตอบ
  ระบบบันทึกเหตุผลแล้วถามใหม่สัปดาห์หน้า ดีกว่าปล่อยให้เงียบจนไม่มีใครรู้สถานะ
- **ติ๊กว่าส่งคำขอแล้วก่อนส่งจริง** กันการ์ดซ้อนกันเมื่อรอบใหม่มาถึงก่อน
  ที่ผู้จัดจะตอบรอบเก่า
- **ถ้าไม่มีอีเมลผู้ประสานงาน ระบบไม่เดา** แต่รายงานในอีเมลสรุปวันจันทร์ว่า
  นี่คืองานที่ระบบทำต่อเองไม่ได้

## 14. สิ่งที่แก้ในเวอร์ชัน 0.3

| เรื่อง | เดิม | ใหม่ |
|---|---|---|
| ค่าใช่หรือไม่ใช่ | เก็บเป็นข้อความ `TRUE` / `FALSE` | เปลี่ยนเป็น `ใช่` / `ไม่ใช่` |
| ข้อมูลปี 2568 ซ้ำ | หลักสูตร 61 รายการ มีซ้ำ 30 แถว | ตัดซ้ำเหลือ 37 รายการ |
| อีเมลพนักงาน | ว่างทั้งหมด 29 คน | กรอกแล้ว 25 คน จากรายชื่อที่ฝ่ายไอทีส่งมา |
| หลักสูตรที่รู้แค่เดือน | ข้ามไป รอคนกรอก | ส่งการ์ดให้ผู้จัดเลือกวัน |
| การ์ดอ้างฟิลด์ที่ไม่มีจริง | คู่มือข้ามขั้นประกอบข้อมูล | เพิ่มหัวข้อ 3 อธิบายขั้น Select |
| Flow B ส่งการ์ดซ้อน | หมดเวลา 3 วัน ชนกับรอบวันที่ 4 | หมดเวลา `P2DT20H` และติ๊กก่อนส่ง |
| ขั้นทดสอบการปลอมตัว | ทำไม่ได้จริง เพราะการ์ดอยู่ในแชท 1:1 | ย้ายไปเป็นการทดสอบของเส้นทางอีเมล |
| หลักสูตรที่จบก่อนเปิดระบบ | ไม่มีทางเก็บผล | เพิ่ม Flow F รันมือครั้งเดียว |
| สคริปต์ตายเพราะวันที่ผิดปฏิทิน | `ValueError` กลางทาง | คืนค่าว่างแล้วรายงานในชีตตรวจสอบ |

**เหตุผลที่เลิกใช้ `TRUE` / `FALSE`** เมื่อผู้ใช้พิมพ์ `TRUE` ลงเซลล์เอง
Excel จะแปลงเป็นค่าตรรกะทันที ทำให้คอลัมน์เดียวมีทั้งข้อความและค่าตรรกะปนกัน
สูตรจัดรูปแบบตามเงื่อนไขที่เทียบกับข้อความจะไม่ตรงอีกต่อไป ช่องจะไม่เปลี่ยนสี
และตัวกรองใน Flow จะข้ามแถวนั้นโดยไม่มีข้อผิดพลาดใด ๆ ปรากฏ
คำว่า `ใช่` กับ `ไม่ใช่` ไม่ถูกแปลง จึงปลอดภัยกว่า

- **คอลัมน์ อีเมลหัวหน้า ยังว่างทั้งคอลัมน์** Flow B ใช้ตอนทวงครั้งที่สอง
