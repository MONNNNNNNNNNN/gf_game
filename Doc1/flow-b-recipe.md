# สูตรสร้าง Flow B ยืนยันหลังอบรมจบ

Flow B ถามพนักงานว่าเข้าอบรมจริงหรือไม่ แล้วติ๊กช่อง `เข้าอบรมแล้ว` ให้อัตโนมัติ

สร้างหลังจาก Flow A ทำงานได้แล้ว เพราะโครงสร้างเหมือนกันเกือบทั้งหมด

---

## ทำไมใช้ การอนุมัติ ไม่ใช่การ์ด Teams กับอีเมลแยกกัน

โจทย์คือพนักงานต้องกดได้ทั้งใน Teams และในอีเมล และกดซ้ำแล้วต้องไม่พัง

ถ้าทำสองทางแยกกัน จะต้องแก้สามปัญหาเอง คือส่งสองที่ รับคำตอบสองทาง
และกันไม่ให้คำตอบสองทางชนกัน

action **การอนุมัติ → เริ่มต้นและรอการอนุมัติ** แก้ทั้งสามข้อให้เสร็จในตัวเดียว

- ส่งเข้าแอป Approvals ใน Teams **และ** ส่งอีเมลที่มีปุ่ม พร้อมกันอัตโนมัติ
- กดที่ไหนก็ได้ ผลเดียวกัน
- กดที่หนึ่งแล้ว อีกที่จะขึ้นว่าตอบไปแล้ว กดซ้ำไม่ได้และไม่เกิดข้อมูลซ้ำ
- ตั้งข้อความปุ่มเองได้ ไม่ต้องใช้คำว่า อนุมัติ หรือ ปฏิเสธ

เป็นตัวเชื่อมต่อมาตรฐาน อยู่ในสิทธิ์ Microsoft 365 ที่บริษัทมีแล้ว

**ข้อแลกเปลี่ยน** action นี้หยุดรอจนกว่าจะมีคนกดหรือหมดเวลา ระหว่างนั้น
run จะค้างอยู่ในสถานะกำลังทำงาน เป็นเรื่องปกติ แต่ต้องตั้งเวลาหมดอายุไว้
มิฉะนั้นจะมี run ค้างสะสมจนดูสถานะไม่รู้เรื่อง

## 7 นับว่าจบไปแล้วกี่วัน

action **เขียน** ชื่อ `DaysSince`

```
if(empty(outputs('Training')?['วันจบ']), -999, div(sub(ticks(outputs('Today')), ticks(outputs('Training')?['วันจบ'])), 864000000000))
```

กลับด้านกับ Flow A ตรงนี้เอาวันนี้ลบวันจบ ได้จำนวนวันที่ผ่านมาแล้ว

## 8 ตัดสินว่าถึงเวลาถามหรือยัง

action **เขียน** ชื่อ `ShouldAsk`

```
and(equals(toLower(string(outputs('Training')?['ใช้แจ้งเตือน'])),'true'),equals(outputs('Training')?['สถานะการอนุมัติ'],'อนุมัติ'),equals(outputs('Training')?['สถานะวันที่'],'ยืนยันแล้ว'),equals(outputs('Employee')?['สถานะ'],'ทำงานอยู่'),not(empty(outputs('Employee')?['อีเมล Microsoft 365'])),not(equals(toLower(string(items('ForEachRow')?['เข้าอบรมแล้ว'])),'true')),empty(items('ForEachRow')?['เหตุผลที่ไม่ได้เข้า']),not(equals(toLower(string(items('ForEachRow')?['ขอยืนยันแล้ว'])),'true')),greaterOrEquals(outputs('DaysSince'),1))
```

**ระหว่างทดสอบ ล็อกไว้ที่หลักสูตรทดสอบ** ใส่ `equals(items('ForEachRow')?['รหัสหลักสูตร'],'TR-2569-006'),`
ต่อจาก `and(` ตัวแรก แล้วลบออกตอนเปิดใช้จริง มิฉะนั้นถ้ามีคนกดอนุมัติหลักสูตรจริงที่จบไปแล้ว
พนักงานจริงทั้งหลักสูตรจะได้คำขอตั้งแต่รอบทดสอบ

เงื่อนไขทั้งเก้าข้อ

| เงื่อนไข | เหตุผล |
|---|---|
| ใช้แจ้งเตือน เป็น ใช่ | ข้ามหลักสูตรปีที่ผ่านมา |
| สถานะการอนุมัติ เป็น อนุมัติ | แผนที่ยังไม่อนุมัติไม่ต้องถาม |
| สถานะวันที่ เป็น ยืนยันแล้ว | ไม่มีวันจบก็คำนวณไม่ได้ |
| พนักงานยังทำงานอยู่ | คนลาออกไม่ต้องถาม |
| มีอีเมล | ไม่มีอีเมลส่งไม่ได้ |
| เข้าอบรมแล้ว ไม่ใช่ ใช่ (ว่างก็นับ) | คนที่ยืนยันแล้วไม่ต้องถามซ้ำ |
| เหตุผลที่ไม่ได้เข้า ว่าง | คนที่ตอบว่าไม่ได้เข้าถือว่าปิดรายการแล้ว |
| ขอยืนยันแล้ว ไม่ใช่ ใช่ (ว่างก็นับ) | **กันส่งคำขอซ้ำ ข้อสำคัญที่สุด** |
| จบไปแล้วอย่างน้อย 1 วัน | ยังไม่จบก็ยังไม่ต้องถาม |

ต่างจาก Flow A ตรงที่ไม่ได้เจาะจงว่าต้องเป็นวันที่ 1, 4 หรือ 8
ใช้ `ขอยืนยันแล้ว` คุมแทน จึงถามครั้งเดียวต่อคนต่อหลักสูตร
และเก็บตกหลักสูตรที่จบไปนานแล้วก่อนเปิดระบบได้ในรอบเดียว

## 10 อ่านแถวสดอีกครั้ง แล้วติ๊กว่าส่งคำขอแล้ว ทำก่อนส่ง

ข้อมูลที่ `ReadEnrollments` อ่านไว้เป็นภาพ ณ เวลาเริ่ม run แต่ run ของ Flow B

ใน run เก่า run ใหม่จะถามแถวนั้นไปก่อน แล้ว run เก่าตามมาถามซ้ำด้วยข้อมูลเก่า
พนักงานจะได้คำขอสองใบ

- อ่านแถวสดก่อนติ๊ก ถ้ามี run อื่นติ๊กไปแล้ว ให้ข้าม

| ตัวเลือกการตอบกลับ | `เข้าอบรมแล้ว` และ `ไม่ได้เข้าอบรม` ใส่ทีละบรรทัด |

จึงเว้นบรรทัดว่างคั่นทุกบรรทัด

```
เรียน @{outputs('Employee')?['ชื่อ-นามสกุล']}

การอบรมที่ท่านลงทะเบียนไว้ได้สิ้นสุดลงแล้ว กรุณากดยืนยันเพื่อบันทึกประวัติ

**หัวข้อ** @{outputs('Training')?['หัวข้ออบรม']}

**วันที่** @{outputs('ThaiDate')}

**เวลา** @{outputs('Training')?['ช่วงเวลา']}

ท่านจะได้รับคำขอนี้ทั้งในแอป Approvals ของ Teams และทางอีเมล
กดที่ใดที่หนึ่งก็พอ กดแล้วอีกทางจะขึ้นว่าตอบแล้วโดยอัตโนมัติ

หากท่านไม่ได้เข้าอบรม กรุณากดปุ่ม ไม่ได้เข้าอบรม และพิมพ์เหตุผลในช่องความคิดเห็น

```

จากนั้นกดที่จุดสามจุดของ action เลือก **การตั้งค่า** แล้วตั้ง
**ระยะหมดเวลา** เป็น `P29D`

บริษัทเลือกรอคำตอบประมาณ 30 วัน แล้วให้ผู้ดูแลตามเองในชีต ไม่ส่งซ้ำ

ถ้าตั้ง `P30D` run จะถูกตัดทิ้งก่อน action ถึงเวลาหมด ขั้นบันทึกว่าไม่มีคำตอบในข้อ 14 จะไม่ได้ทำงาน

## 13 บันทึกคำตอบ

ต่อจาก `AskConfirm` ในกิ่งเดียวกัน
เพิ่ม **เงื่อนไข** ชื่อ `IsAttended`

| ช่อง | ค่า |
|---|---|
| ซ้าย | `fx` วาง `outputs('AskConfirm')?['body/outcome']` |
| ตัวดำเนินการ | เท่ากับ |
| ขวา | พิมพ์ `เข้าอบรมแล้ว` |

ต้องตรงกับข้อความในช่อง ตัวเลือกการตอบกลับ ทุกตัวอักษร รวมเว้นวรรค

### กิ่ง จริง ชื่อ `SaveAttended`

**Excel Online (Business) → Update a row**

| ช่อง | ค่า |
|---|---|
| Key Column | รหัสการลงทะเบียน |

| เข้าอบรมแล้ว | `fx` `true` |

| ช่องทางที่ยืนยัน | พิมพ์ `Approvals` |

### กิ่ง เท็จ

กิ่งนี้มีได้สองกรณี พนักงานกด ไม่ได้เข้าอบรม หรือคำขอถูกยกเลิกโดยไม่มีใครตอบ
กรณีหลัง `outcome` เป็นค่าว่าง และ `responses` เป็นรายการว่าง ถ้าบันทึกเหมือนกรณีแรก
action จะพังเพราะไม่มีคำตอบให้อ่าน จึงต้องแยกด้วยเงื่อนไขอีกชั้น

**เงื่อนไข** ชื่อ `IsAbsent` ซ้าย `fx` `outputs('AskConfirm')?['body/outcome']` เท่ากับ พิมพ์ `ไม่ได้เข้าอบรม`

กิ่ง เท็จ ของ `IsAbsent` คือคำขอถูกยกเลิก เพิ่ม **Update a row** ชื่อ `MarkCancelled`
Key เหมือน `MarkAsked` ช่อง `ช่องทางที่ยืนยัน` พิมพ์ `คำขอถูกยกเลิก` ช่องอื่นเว้นว่าง
`ขอยืนยันแล้ว` ยังติ๊กอยู่ ระบบจึงไม่ถามซ้ำ ถ้าต้องการถามใหม่ ผู้ดูแลเอาติ๊กออกเอง

กิ่ง จริง ของ `IsAbsent` ใส่ `SaveAbsent`

#### `SaveAbsent`

**Update a row** เหมือนกัน แต่

| ช่อง | ค่า |
|---|---|
| เข้าอบรมแล้ว | `fx` `false` |
| เหตุผลที่ไม่ได้เข้า | `fx` วาง `if(empty(first(outputs('AskConfirm')?['body/responses'])?['comments']),'ไม่ได้ระบุเหตุผล',first(outputs('AskConfirm')?['body/responses'])?['comments'])` |
| วันเวลาที่ยืนยัน, ผู้ยืนยัน, ช่องทางที่ยืนยัน | เหมือนกิ่งจริง |

`first()` แทน `[0]` เพราะถ้ารายการคำตอบว่าง `[0]` ทำให้ Flow พัง ส่วน `first()` ได้ค่าว่าง
`empty()` ใช้กันกรณีพนักงานกดปุ่มโดยไม่พิมพ์ความคิดเห็น ซึ่งอาจได้ทั้ง null และข้อความว่าง
`coalesce()` จับได้แค่ null จึงใช้ไม่ได้ที่นี่

## 14 กรณีหมดเวลาไม่มีใครตอบ

บริษัทเลือก **ไม่ส่งซ้ำ** ผู้ดูแลตามเองในชีต Flow แค่ทิ้งร่องรอยไว้ให้กรองหาได้

`ขอยืนยันแล้ว` ยังเป็น `ใช่` อยู่ รอบถัดไปจึงไม่ถามซ้ำโดยไม่ต้องทำอะไรเพิ่ม

เพิ่ม **Update a row** ชื่อ `MarkNoAnswer` ต่อจากกล่อง `IsAttended` (นอกกล่อง ข้างใต้)

| ช่อง | ค่า |
|---|---|
| Key | เหมือน `MarkAsked` |
| ช่องทางที่ยืนยัน | พิมพ์ `ไม่มีคำตอบภายใน 30 วัน` |

แล้วกดจุดสามจุดของ `MarkNoAnswer` → **การตั้งค่า** → **เรียกใช้หลังจาก** (Run after)
ติ๊กเฉพาะ **ถูกข้าม** (is skipped) เอา **สำเร็จ** ออก

เหตุผล ถ้าพนักงานตอบ `IsAttended` ทำงานและสำเร็จ `MarkNoAnswer` จึงไม่ทำ
ถ้าหมดเวลา `AskConfirm` ไม่สำเร็จ `IsAttended` ถูกข้าม `MarkNoAnswer` จึงทำงาน

ผู้ดูแลกรองคอลัมน์ `ช่องทางที่ยืนยัน` = `ไม่มีคำตอบภายใน 30 วัน` แล้วถามคนนั้นเอง
ได้คำตอบแล้วแก้ `เข้าอบรมแล้ว` และเปลี่ยน `ช่องทางที่ยืนยัน` เป็น `แก้โดยผู้ดูแล`

## 15 ทดสอบ

**ก่อนรันครั้งแรก ตรวจชีต หลักสูตร** ว่ามีแค่ `TR-2569-006` ที่ `สถานะการอนุมัติ` เป็น `อนุมัติ`
และจบไปแล้ว ถ้ามีหลักสูตรจริงที่อนุมัติแล้วและจบไปแล้ว พนักงานจริงจะได้คำขอยืนยันตั้งแต่รอบทดสอบ
ให้ตั้ง `ใช้แจ้งเตือน` ของหลักสูตรนั้นเป็น `ไม่ใช่` ไว้ก่อนจนกว่าจะเปิดใช้จริง

เตรียมข้อมูลที่แถว `ENR-2569-0256`

| คอลัมน์ | ตั้งเป็น |
|---|---|
| เข้าอบรมแล้ว | `ไม่ใช่` |
| ขอยืนยันแล้ว | `ไม่ใช่` |
| เหตุผลที่ไม่ได้เข้า | ลบให้ว่าง |

และที่ `TR-2569-006` แก้ `วันเริ่ม` และ `วันจบ` เป็นเมื่อวาน

| ขั้น | ต้องเห็น |
|---|---|
| 1 | คำขอเข้าแอป Approvals ใน Teams |
| 2 | อีเมลคำขอที่มีปุ่มสองปุ่ม เข้ากล่องจดหมายด้วย |
| 3 | กดปุ่มในอีเมล แล้วกลับไปดูใน Teams ต้องขึ้นว่าตอบแล้ว |
| 4 | ในไฟล์ `เข้าอบรมแล้ว` เป็น `ใช่` และ `ช่องทางที่ยืนยัน` เป็น `Approvals` |
| 5 | สั่งรันซ้ำ ต้องไม่มีคำขอใบที่สอง |

ขั้นที่ 3 คือการพิสูจน์ว่าสองช่องทางเชื่อมกันจริง
ขั้นที่ 5 พิสูจน์ว่า `ขอยืนยันแล้ว` กันซ้ำได้

## ข้อควรรู้

**run จะค้างในสถานะกำลังทำงาน** ตราบใดที่ยังไม่มีใครกด เป็นเรื่องปกติของ
action ที่รอคำตอบ ไม่ใช่อาการค้าง ดูได้ที่ประวัติการรัน

**Concurrency 50 ห้ามลืม** ถ้าไม่เปิด ลูปทำทีละแถว และแถวที่สองจะไม่ได้รับคำขอ
จนกว่าคนแรกจะกด ข้อนี้สำคัญกว่าใน Flow A มาก เพราะ Flow A ไม่รอ แต่ Flow B รอ

**ถ้าวันเดียวมีคนต้องยืนยันเกิน 50 คน** คนที่ 51 เป็นต้นไปรอคิว
`FreshRow` กันคำขอซ้ำได้ แต่คนเหล่านั้นจะได้คำขอช้า
บริษัทนี้มีพนักงาน 32 คน จึงไม่ถึงเพดาน
