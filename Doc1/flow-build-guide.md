# คู่มือสร้าง Flow ใน Power Automate

ระบบแจ้งเตือนการอบรมพนักงาน — บริษัท เอ.จี.ยูนิเวอร์แซล จำกัด
ใช้คู่กับไฟล์ `build/ระบบอบรม-ต้นแบบ.xlsx`

เอกสารนี้สำหรับผู้สร้างระบบ ถ้าต้องการคู่มือสำหรับผู้ใช้งานประจำวัน
ดู `docs/user-manual.md`

---

## ภาพรวม Flow

| Flow | ทำงานเมื่อ | หน้าที่ |
|---|---|---|
| A | ทุกวัน 08:00 | แจ้งเตือนล่วงหน้า 7 วัน และ 1 วัน |
| B | ทุกวัน 08:00 | หลังอบรมจบ ส่งการ์ดให้กดยืนยัน และบันทึกคำตอบ |
| D | จันทร์ 09:00 | สรุปงานค้างส่งผู้ดูแลระบบทั้ง 8 คน |
| ~~E~~ | ยกเลิก | ผู้ดูแลตกลงวันกับผู้จัดเองนอกระบบ ดูหัวข้อ 8 |
| F | รันมือครั้งเดียว | เก็บผลย้อนหลังของหลักสูตรที่จบไปก่อนเปิดระบบ |

สร้างตามลำดับ A → B → D และเก็บ F ไว้ทำตอนจะเปิดใช้จริง

## 0. ตรวจสิทธิ์การใช้งานก่อน ใช้เวลาสองนาที

ไม่ต้องไล่ตรวจสิทธิ์ของพนักงานทุกคน Flow ทำงานภายใต้บัญชีของ **เจ้าของ Flow
เพียงบัญชีเดียว** พนักงานคนอื่นเป็นเพียงผู้รับข้อความ ไม่ต้องมีสิทธิ์
Power Automate ใด ๆ ขอเพียงมีบัญชี Microsoft 365 ซึ่งบริษัทยืนยันแล้วว่ามีครบ

วิธีตรวจ

1. เข้า `make.powerautomate.com` ด้วยบัญชีที่จะเป็นเจ้าของระบบ
2. กด **สร้าง** แล้วเลือก **โฟลว์ระบบคลาวด์ตามกำหนดการ**
3. ถ้าสร้างได้โดยไม่ขึ้นข้อความขอให้ซื้อสิทธิ์เพิ่ม แปลว่าใช้ได้
4. เพิ่มขั้นตอน แล้วค้นหาตัวเชื่อมต่อสามตัวนี้ ต้องไม่มีเพชรสีน้ำเงินกำกับ

   - Excel Online (Business)
   - Microsoft Teams
   - Office 365 Outlook

ระบบนี้ใช้เฉพาะตัวเชื่อมต่อมาตรฐาน ไม่ใช้ HTTP, Dataverse หรือ custom connector
จึงไม่ต้องซื้อ Power Automate Premium

**เพิ่มเจ้าของร่วมตั้งแต่วันแรก** ที่หน้ารายละเอียด Flow กด แก้ไข ในช่อง เจ้าของ
แล้วเพิ่มอีกอย่างน้อยหนึ่งคน ถ้าเจ้าของบัญชีเดียวลาออก บัญชีจะถูกลบและ Flow
ทุกตัวหยุดพร้อมกัน

## 1. เตรียมที่เก็บไฟล์

Power Automate อ่านและเขียนไฟล์ Excel ได้จาก SharePoint และ OneDrive for
Business เท่านั้น ทั้งสองใช้ตัวเชื่อมต่อ Excel Online (Business) เหมือนกัน
ต่างแค่ค่าในช่อง **ตำแหน่ง** File Server ภายในใช้ไม่ได้

### 1.1 ถ้าไฟล์อยู่บน OneDrive

ใช้ได้ทันที แต่ต้องตรวจสามข้อ

**หนึ่ง ต้องเป็น OneDrive for Business** สังเกตจากบัญชีที่ล็อกอิน ถ้าเป็นอีเมล
บริษัทคือถูกต้อง บัญชีส่วนตัวแบบ outlook.com เป็นคนละตัวเชื่อมต่อ และไม่มีการ
ยืนยันตัวตนขององค์กรให้ใช้

**สอง ไฟล์ต้องอยู่ใน OneDrive ของบัญชีเดียวกับเจ้าของ Flow** ช่องตำแหน่งจะแสดง
เฉพาะ OneDrive ของบัญชีที่เชื่อมต่อ ไฟล์ที่คนอื่นแชร์มาจะไม่ปรากฏในรายการ

**สาม ถ้าเป็นโฟลเดอร์ที่ sync ลงเครื่อง ต้องมั่นใจว่า sync ขึ้นคลาวด์จริง**
Power Automate อ่านสำเนาบนคลาวด์ ไม่ได้อ่านโฟลเดอร์บนเครื่อง

### 1.2 เหตุผลที่ยังควรย้ายไป SharePoint ในภายหลัง

OneDrive ผูกกับตัวบุคคล เมื่อเจ้าของบัญชีลาออก บัญชีถูกลบ และ OneDrive
ถูกล้างหลังพ้นช่วงเก็บรักษา ค่าเริ่มต้น 30 วัน ข้อมูลการอบรมทั้งหมดหายพร้อมกัน

SharePoint ผูกกับไซต์ ไม่ผูกกับคน ทุก Team ใน Microsoft Teams มีไซต์ของตัวเอง
อยู่แล้ว วางไฟล์ในแท็บ ไฟล์ ของ Team ได้เลย ไม่ต้องสร้างไซต์ใหม่

ย้ายด้วยคำสั่ง **ย้ายไป** ใน OneDrive บนเว็บ ประวัติเวอร์ชันตามไปด้วย
ตอนย้าย แก้แค่ช่อง ตำแหน่ง กับ ไลบรารีเอกสาร ตรรกะของ Flow ไม่ต้องแก้

### 1.3 ตั้งค่าหลังวางไฟล์

1. เปลี่ยนชื่อไฟล์เป็น `ระบบอบรม.xlsx`
2. ให้สิทธิ์แก้ไขเฉพาะผู้ดูแลระบบ คนอื่นให้สิทธิ์อ่านหรือไม่ให้เลย
3. **เปิดไฟล์นี้ด้วย Excel บนเว็บเท่านั้น** ถ้าเปิดค้างด้วย Excel บนเครื่อง
   ไฟล์จะถูกล็อก Flow เขียนข้อมูลไม่ได้ และคำยืนยันของพนักงานจะหายโดยไม่มี
   ข้อความเตือน

## 2. การอ่านข้อมูล ทำเหมือนกันทุก Flow

ใช้ action **Excel Online (Business) → แสดงรายการแถวที่มีอยู่ในตาราง** สามครั้ง
ตั้งชื่อขั้นตอนว่า `อ่านผู้เข้าอบรม`, `อ่านหลักสูตร`, `อ่านพนักงาน`

ถ้าไฟล์อยู่บน OneDrive

| ช่อง | ค่า |
|---|---|
| ตำแหน่ง | OneDrive for Business |
| ไลบรารีเอกสาร | OneDrive |
| ไฟล์ | เส้นทางไฟล์ใน OneDrive ของบัญชีที่เชื่อมต่อ |
| ตาราง | `Enrollments` / `Trainings` / `Employees` |

ถ้าไฟล์อยู่บน SharePoint ให้เปลี่ยน ตำแหน่ง เป็นไซต์ และ ไลบรารีเอกสาร
เป็น Documents ที่เหลือเหมือนกัน

**สำคัญมาก** กดจุดสามจุดของ action เลือก **ตั้งค่า** แล้วตั้ง
**รูปแบบวันที่และเวลา** เป็น **ISO 8601**

ถ้าไม่ตั้ง Excel จะส่งวันที่กลับมาเป็นตัวเลขอนุกรม เช่น `46262` แทน `2026-08-28`
แล้วการคำนวณวันทั้งหมดจะผิด นี่เป็นจุดที่พลาดกันบ่อยที่สุด ถ้าเผลอใช้ไปแล้ว
แปลงกลับด้วย `addDays('1899-12-30', int(<ค่าที่ได้>))`

## 3. การประกอบข้อมูลก่อนส่งการ์ด ขั้นตอนที่ห้ามข้าม

การ์ดในโฟลเดอร์ `flows/` ต้องการข้อมูลจากทั้งสามตารางรวมกัน เช่น ชื่อพนักงาน
อยู่ในตาราง Employees แต่หัวข้ออบรมอยู่ในตาราง Trainings ส่วนรหัสการลงทะเบียน
อยู่ในตาราง Enrollments

ตารางเดียวไม่มีครบ จึงต้องประกอบเป็นรายการใหม่ก่อนเข้าลูปส่งการ์ด
ถ้าข้ามขั้นนี้ การ์ดจะขึ้นค่าว่างทุกช่อง

**วิธีทำ** หลังกรองรายชื่อผู้เข้าอบรมของหลักสูตรหนึ่งได้แล้ว ใส่ action
**การดำเนินการข้อมูล → เลือก** ตั้งชื่อว่า `ประกอบข้อมูลผู้รับ`

- **จาก** ใส่ผลลัพธ์ของ action กรองอาร์เรย์
- กดสลับเป็นโหมดข้อความ แล้วใส่คีย์เหล่านี้ ค่าของแต่ละคีย์ดึงจากตารางที่เกี่ยวข้อง

| คีย์ | ที่มา |
|---|---|
| `รหัสการลงทะเบียน` | จากแถว Enrollments ที่กำลังวน |
| `ชื่อพนักงาน` | ค้นใน `อ่านพนักงาน` ด้วย `รหัสพนักงาน` |
| `อีเมล` | ค้นใน `อ่านพนักงาน` ด้วย `รหัสพนักงาน` |
| `อีเมลหัวหน้า` | ค้นใน `อ่านพนักงาน` ด้วย `รหัสพนักงาน` |
| `หัวข้ออบรม` | จากหลักสูตรที่กำลังวนอยู่ในลูปชั้นนอก |
| `สถาบันผู้จัดอบรม`, `วิทยากร`, `สถานที่`, `รูปแบบ`, `ช่วงเวลา` | จากหลักสูตรเดียวกัน |
| `วันที่แบบไทย` | คำนวณตามหัวข้อ 4 |
| `หัวเรื่อง` | ข้อความหัวการ์ด เช่น `แจ้งเตือนล่วงหน้า 7 วัน` |

**ภาษานิพจน์ไม่มีฟังก์ชัน `filter()`** การค้นแถวจากอาร์เรย์ต้องใช้ action
**การดำเนินการข้อมูล → กรองอาร์เรย์** แล้วหยิบผลตัวแรกด้วย `first()`

ตัวอย่างการค้นพนักงานหนึ่งคน

1. action **กรองอาร์เรย์** ชื่อ `FilterEmployee`
   - จาก `outputs('อ่านพนักงาน')?['body/value']`
   - เงื่อนไข `item()?['รหัสพนักงาน']` เท่ากับ `items('<ชื่อลูป>')?['รหัสพนักงาน']`
2. action **เขียน** ชื่อ `Employee` ค่า `first(body('FilterEmployee'))`
3. อ้างถึงด้วย `outputs('Employee')?['ชื่อ-นามสกุล']`

`body()` ใช้กับกรองอาร์เรย์ ส่วน `outputs()` ใช้กับเขียน สลับกันไม่ได้

ดูตัวอย่างที่สร้างจริงแล้วใน `docs/flow-a-recipe.md` ข้อ 5 และ 6

จากนั้นวน **นำไปใช้กับแต่ละรายการ** บนผลลัพธ์ของ `ประกอบข้อมูลผู้รับ`
ตั้งชื่อลูปว่า `วนทีละคน` ซึ่งเป็นชื่อที่การ์ดทุกใบอ้างถึง

## 4. การแสดงวันที่เป็น พ.ศ.

ไฟล์เก็บวันที่เป็น ค.ศ. เพื่อให้คำนวณได้ แต่พนักงานต้องเห็นเป็น พ.ศ.

อบรมวันเดียว

```
concat(
  formatDateTime(item()?['วันเริ่ม'], 'dd/MM/'),
  add(int(formatDateTime(item()?['วันเริ่ม'], 'yyyy')), 543)
)
```

อบรมหลายวัน

```
concat(
  formatDateTime(item()?['วันเริ่ม'], 'dd'), '-',
  formatDateTime(item()?['วันจบ'], 'dd/MM/'),
  add(int(formatDateTime(item()?['วันจบ'], 'yyyy')), 543)
)
```

ผลลัพธ์ `27/08/2569` และ `08-09/08/2569` ตรงกับรูปแบบที่ใช้ในไฟล์เดิม

## 5. Flow A — แจ้งเตือนล่วงหน้า

**ทริกเกอร์** เกิดซ้ำ ทุก 1 วัน เวลา 08:00 เขตเวลา Bangkok

1. อ่านสามตารางตามหัวข้อ 2
2. ตัวแปร `วันนี้` ชนิดสตริง ค่า
   `formatDateTime(convertFromUtc(utcNow(),'SE Asia Standard Time'),'yyyy-MM-dd')`
3. **กรองอาร์เรย์** จาก `อ่านหลักสูตร` เก็บเฉพาะแถวที่
   - `ใช้แจ้งเตือน` เท่ากับ `ใช่`
   - `สถานะการอนุมัติ` เท่ากับ `อนุมัติ`
   - `สถานะวันที่` เท่ากับ `ยืนยันแล้ว`
4. **นำไปใช้กับแต่ละรายการ** ตั้งชื่อ `วนหลักสูตร`
   - `ระยะห่าง` = `div(sub(ticks(item()?['วันเริ่ม']), ticks(variables('วันนี้'))), 864000000000)`
   - ถ้า `ระยะห่าง` ไม่ใช่ 7 และไม่ใช่ 1 ให้ข้าม
   - ตั้ง `คอลัมน์ที่ต้องติ๊ก` เป็น `แจ้งล่วงหน้า 7 วันแล้ว` หรือ
     `แจ้งล่วงหน้า 1 วันแล้ว` ตามค่าที่ได้
   - **กรองอาร์เรย์** จาก `อ่านผู้เข้าอบรม` เอาแถวที่ `รหัสหลักสูตร` ตรงกัน
     และคอลัมน์ที่ต้องติ๊กยังเป็น `ไม่ใช่`
   - ประกอบข้อมูลตามหัวข้อ 3 แล้ววน `วนทีละคน`
     - ถ้าพนักงานสถานะไม่ใช่ `ทำงานอยู่` หรืออีเมลว่าง ให้ข้าม
     - ส่งการ์ด `flows/card-reminder.json` ด้วย
       **Microsoft Teams → โพสต์การ์ดที่ปรับเปลี่ยนได้ไปยังผู้ใช้หรือช่อง Teams**
       โพสต์เป็น Flow bot ไปยังผู้ใช้ที่อีเมลของพนักงาน
     - **อัปเดตแถว** ตาราง `Enrollments` คอลัมน์คีย์ `รหัสการลงทะเบียน`
       ตั้งคอลัมน์ที่ต้องติ๊กเป็น `ใช่`

การติ๊กหลังส่งสำเร็จ ทำให้สั่งรันซ้ำแล้วพนักงานไม่ได้รับข้อความซ้ำ

ตั้ง Concurrency Control ของ `วนทีละคน` เป็น 10 ห้ามเกินนี้ เพราะการเขียนกลับ
เข้า Excel พร้อมกันมากเกินไปจะชนกัน

## 6. Flow B — ยืนยันหลังอบรมจบ

> **ล้าสมัย** Flow B ที่ใช้งานจริงสร้างตาม `docs/flow-b-recipe.md` (Approvals) หัวข้อ 6 และ 7 ในไฟล์นี้เป็นแบบเดิม

**ทริกเกอร์** เกิดซ้ำ ทุก 1 วัน เวลา 08:00 เขตเวลา Bangkok

1. กรองหลักสูตรเหมือน Flow A แต่คำนวณจาก `วันจบ`
2. เก็บเฉพาะหลักสูตรที่ `วันจบ` ผ่านมาแล้ว 1, 4 หรือ 8 วัน
3. กรอง `อ่านผู้เข้าอบรม` เอาแถวที่
   - `เข้าอบรมแล้ว` เท่ากับ `ไม่ใช่`
   - `เหตุผลที่ไม่ได้เข้า` ว่าง คนที่ตอบแล้วว่าไม่ได้เข้าถือว่าปิดรายการ
   - **`แจ้งหลังอบรมแล้ว` เท่ากับ `ไม่ใช่`** ข้อนี้กันการ์ดซ้อน ดูคำอธิบายด้านล่าง
4. ประกอบข้อมูลตามหัวข้อ 3 แล้ววน `วนทีละคน`
5. **อัปเดตแถว** ตั้ง `แจ้งหลังอบรมแล้ว` เป็น `ใช่` และ `จำนวนครั้งที่ทวง` บวกหนึ่ง
   **ก่อน** ส่งการ์ด
6. ส่งการ์ด `flows/card-confirm.json` ด้วย
   **Microsoft Teams → โพสต์การ์ดที่ปรับเปลี่ยนได้และรอการตอบกลับ**
   - **หมดเวลา** ตั้งเป็น `P2DT20H` คือ 2 วัน 20 ชั่วโมง
   - **อัปเดตข้อความ** ตั้งเป็น `บันทึกคำตอบเรียบร้อยแล้ว ขอบคุณค่ะ`
7. หลังการ์ดคืนค่า ให้บันทึกคำตอบตามหัวข้อ 7
8. ถ้าหมดเวลาโดยไม่มีคำตอบ ให้ตั้ง `แจ้งหลังอบรมแล้ว` กลับเป็น `ไม่ใช่`
   เพื่อให้รอบถัดไปส่งใหม่ได้

**เหตุผลที่ต้องติ๊กก่อนส่ง และหมดเวลาที่ 2 วัน 20 ชั่วโมง**

action ที่รอการตอบกลับจะค้าง Flow run ไว้จนกว่าจะมีคนกดหรือหมดเวลา
ถ้าตั้งหมดเวลาเป็น 3 วันเต็ม การ์ดที่ส่งวันที่ 1 จะหมดเวลาพอดีกับตอนที่รอบ
วันที่ 4 กำลังทำงาน ทั้งสองจะทับกันและพนักงานได้การ์ดสองใบพร้อมกัน

การติ๊ก `แจ้งหลังอบรมแล้ว` ก่อนส่ง บวกกับหมดเวลาที่สั้นกว่าช่วงห่างของรอบ
ทำให้ไม่มีทางที่การ์ดสองใบจะค้างอยู่พร้อมกัน

ถ้าครบ 8 วันแล้วยังไม่ตอบ ให้ส่งสำเนาถึง `อีเมลหัวหน้า` ด้วย

## 7. บันทึกคำตอบ

ไม่ใช่ Flow แยก แต่เป็นขั้นตอนต่อท้าย Flow B ทันทีหลังได้รับคำตอบ
เพราะการรับคำตอบด้วย Flow แยกต้องใช้ HTTP trigger ซึ่งเป็น Premium

อ่านคำตอบด้วยนิพจน์เหล่านี้

```
body('โพสต์การ์ดและรอการตอบกลับ')?['data']?['response']
body('โพสต์การ์ดและรอการตอบกลับ')?['data']?['enrollmentId']
body('โพสต์การ์ดและรอการตอบกลับ')?['data']?['reasonChoice']
body('โพสต์การ์ดและรอการตอบกลับ')?['data']?['reasonDetail']
body('โพสต์การ์ดและรอการตอบกลับ')?['responder']?['email']
```

ใช้ **Excel Online (Business) → อัปเดตแถว** บนตาราง `Enrollments`
คอลัมน์คีย์ `รหัสการลงทะเบียน` ค่าคีย์คือ `enrollmentId` จากการ์ด

| คอลัมน์ | ค่าที่เขียน |
|---|---|
| เข้าอบรมแล้ว | `ใช่` เมื่อ response เป็น `attended` มิฉะนั้น `ไม่ใช่` |
| วันเวลาที่ยืนยัน | `utcNow()` |
| ผู้ยืนยัน | อีเมลผู้กดปุ่ม |
| ช่องทางที่ยืนยัน | `Teams` |
| เหตุผลที่ไม่ได้เข้า | `reasonChoice` ต่อด้วย `reasonDetail` ถ้ามี |

เมื่อเขียนเสร็จ การจัดรูปแบบตามเงื่อนไขในไฟล์จะเปลี่ยนเซลล์เป็นสีเขียวทันที

**เรื่องการตรวจตัวตน** การ์ดถูกโพสต์ในแชทส่วนตัวระหว่าง Flow bot กับพนักงาน
คนเดียว คนอื่นมองไม่เห็นและกดไม่ได้ ตัวตนจึงเชื่อถือได้โดยไม่ต้องตรวจเพิ่ม
แต่ในเส้นทางอีเมลสำรอง ปุ่มถูกฟอร์เวิร์ดต่อได้ จึงต้องตรวจที่นั่น ดูหัวข้อ 11

## 8. Flow E — ขอให้ผู้จัดเลือกวัน

**ยกเลิกแล้ว 23 กันยายน 2569** บริษัทตัดสินใจให้ผู้ดูแลระบบ 8 คนตกลงวันกับผู้จัดเองนอกระบบ
แล้วกรอก `วันเริ่ม` `วันจบ` ในชีต หลักสูตร เอง ไม่มีการ์ดขอจองวัน ไม่ต้องสร้าง Flow E
หลักสูตรที่ใกล้ช่วงวางแผนแต่ยังไม่มีวัน ไปขึ้นในอีเมลสรุปของ Flow D แทน

## 9. Flow F — เก็บผลย้อนหลัง รันครั้งเดียว

ตอนเริ่มใช้ระบบ มีหลักสูตรที่จบไปแล้วก่อนเปิดระบบ Flow B มองย้อนหลังแค่ 8 วัน
จึงไม่มีทางส่งถึงคนกลุ่มนี้ ถ้าไม่ทำอะไร ประวัติของพวกเขาจะค้างเป็น `ไม่ใช่`
ตลอดไป

สร้าง Flow แบบ **โฟลว์ระบบคลาวด์ทันที** คัดลอกโครงจาก Flow B แล้วแก้สองจุด

- ตัดเงื่อนไข 1, 4, 8 วันออก ใช้แค่ `วันจบ` น้อยกว่าวันนี้
- หัวการ์ดเปลี่ยนเป็นข้อความอธิบายว่าเป็นการเก็บข้อมูลย้อนหลัง
  เช่น `ขอเก็บประวัติย้อนหลัง การอบรมนี้จัดขึ้นเมื่อ ...`

สั่งรันด้วยมือครั้งเดียวตอนเปิดระบบ แล้ว **ปิด Flow นี้ทิ้ง** อย่าปล่อยให้
ทำงานตามกำหนดการ มิฉะนั้นมันจะส่งซ้ำทุกวันให้ทุกคนที่ยังไม่ยืนยัน

ทางเลือกที่ง่ายกว่าถ้าจำนวนไม่มาก คือเปิดไฟล์แล้วติ๊กมือในชีต ผู้เข้าอบรม
แล้วใส่ `ช่องทางที่ยืนยัน` เป็น `เก็บย้อนหลัง`

## 10. Flow D — สรุปงานค้างรายสัปดาห์

**ทริกเกอร์** เกิดซ้ำ ทุกวันจันทร์ 09:00 เขตเวลา Bangkok

รวบรวมสี่รายการ ส่งเป็นอีเมลฉบับเดียวถึงผู้ดูแลระบบทั้ง 8 คน

1. **ยังไม่ยืนยัน** อบรมจบเกิน 8 วันแล้วแต่ `เข้าอบรมแล้ว` ยังไม่ใช่ `ใช่`
   และไม่มีเหตุผลกำกับ
2. **ใกล้ช่วงวางแผนแต่ยังไม่มีวัน** `ใช้แจ้งเตือน` เป็น `ใช่` `สถานะวันที่` ไม่ใช่ `ยืนยันแล้ว`
   และ `ช่วงวางแผนเริ่ม` อยู่ภายใน 30 วันข้างหน้า ผู้ดูแลต้องไปตกลงวันกับผู้จัด
   รายการนี้แทนที่ Flow E ที่ยกเลิกไป
3. **ช่วงวางแผนผ่านไปแล้ว** หลักสูตรที่ `ช่วงวางแผนจบ` เลยวันนี้ไปแล้วแต่ยังไม่มีวัน
   ต้องตัดสินใจว่าเลื่อนปีหน้า หรือจัดไปแล้วแต่ยังไม่บันทึก
4. **ข้อมูลไม่ครบ** พนักงานสถานะทำงานอยู่ที่ยังไม่มีอีเมล

ใช้ **สร้างตาราง HTML** แล้วส่งด้วย **Office 365 Outlook → ส่งอีเมล (V2)**
ถ้าทั้งสี่รายการว่าง ให้ข้ามการส่ง จะได้ไม่มีอีเมลเปล่าทุกสัปดาห์

## 11. ทางสำรองด้วยอีเมล

พนักงานที่ไม่ได้เปิด Teams เป็นประจำ ให้เพิ่มเงื่อนไขใน Flow B ว่า ถ้าการ์ด
หมดเวลาโดยไม่มีคำตอบ ให้ส่งต่อด้วย
**Office 365 Outlook → ส่งอีเมลพร้อมตัวเลือก**

ตั้งตัวเลือกผู้ใช้เป็น `เข้าอบรมแล้ว;ไม่ได้เข้าอบรม` อ่านผลจาก
`body('ส่งอีเมลพร้อมตัวเลือก')?['SelectedOption']` แล้วเขียนกลับตามหัวข้อ 7
แต่ตั้ง `ช่องทางที่ยืนยัน` เป็น `Email`

**ต้องตรวจตัวตนในเส้นทางนี้** ปุ่มในอีเมลถูกฟอร์เวิร์ดต่อได้ เปรียบเทียบ
`body('ส่งอีเมลพร้อมตัวเลือก')?['SubmitterEmail']` กับอีเมลเจ้าของแถว
ถ้าไม่ตรงให้ยกเลิกและบันทึกเหตุการณ์ไว้

ตัวเชื่อมต่อนี้เป็นมาตรฐาน ไม่ต้องซื้อเพิ่ม

## 12. ลำดับการทดสอบก่อนเปิดใช้จริง

อย่าเปิดใช้กับพนักงานทุกคนตั้งแต่วันแรก ใช้สคริปต์ `add-test-row.py`
สร้างข้อมูลทดสอบให้ตรงกับรอบที่ต้องการ

```bash
python3 scripts/add-test-row.py "build/ระบบอบรม-ต้นแบบ.xlsx" "อีเมลคุณ" d7
```

| ขั้น | โหมด | สิ่งที่ต้องเห็น |
|---|---|---|
| 1 | `d7` | ได้การ์ดใน Teams และ `แจ้งล่วงหน้า 7 วันแล้ว` เปลี่ยนเป็น `ใช่` |
| 2 | `d7` รันซ้ำ | **ไม่** ได้การ์ดซ้ำ ถ้าได้ซ้ำแปลว่าขั้นอัปเดตแถวพลาด |
| 3 | `d1` แล้ว `reset` | ได้การ์ดรอบหนึ่งวัน |
| 4 | `done` | ได้การ์ดที่มีปุ่มสองปุ่ม |
| 5 | กด เข้าอบรมแล้ว | เซลล์ `เข้าอบรมแล้ว` เป็น `ใช่` และเป็นสีเขียว |
| 6 | `reset` แล้วกด ไม่ได้เข้าอบรม | มีช่องเลือกเหตุผล และเหตุผลถูกบันทึก |
| 7 | กรอกวันเริ่ม วันจบ ให้หลักสูตรที่ยังไม่มีวัน | `สถานะวันที่` เปลี่ยนเป็น `ยืนยันแล้ว` เอง |
| 8 | สั่งรัน Flow A | หลักสูตรที่เพิ่งได้วัน เข้าคิวแจ้งเตือนเองโดยไม่ต้องแก้อะไร |

ขั้นที่ 8 คือการพิสูจน์ว่าวงจรครบ ตั้งแต่ผู้ดูแลกรอกวัน จนพนักงานได้รับแจ้ง

เมื่อผ่านทั้งแปดข้อ ให้ลบแถวทดสอบแล้วขยายทีละแผนก

```bash
python3 scripts/add-test-row.py "build/ระบบอบรม-ต้นแบบ.xlsx" x remove
```

## 13. สิ่งที่ต้องเฝ้าดูหลังเปิดใช้

  คือมีคนเปิดไฟล์ค้างด้วย Excel บนเครื่อง
- **การ์ดค้างจำนวนมาก** ดูที่ประวัติการรัน ถ้ามี run สถานะกำลังทำงานค้างเกิน
  จำนวนผู้รับจริง แปลว่าหมดเวลาตั้งไว้ยาวเกินช่วงห่างของรอบ
- **ตารางโตขึ้นทุกปี** เมื่อ `Enrollments` เกินประมาณ 2,000 แถว ให้แยกไฟล์
  ตามปี หรือย้ายไปใช้ SharePoint List
